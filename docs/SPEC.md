# 太空舰桥 · SPEC（宪法）
> 项目：Starsea Helm｜星海舵手
> 状态：WIP / 最后更新：2026-09-10（**仅更新状态行** —— 正文仍是 2026-09-01 第三轮重定位版）/ 阶段：**P0 收尾中**（BACKLOG ①–⑧ + ⑨a/⑨b/⑩ 完成，余 ⑪ 的 VFX 与 hitstop；见 `BACKLOG.md`）
> Slogan：在星海的舰桥之上，执掌你的战舰，守望属于自己的星途。

---

## One-liner

第一人称舰桥视角的**据点防守**游戏。飞船在战斗中**视觉上相对静止**（宇宙中以相对姿态呈现，并非真的"停着不动"），敌人从四面围攻；玩家通过**主控室常驻的副炮实时画面**掌握舷窗看不见的战况，并可**切换主视角接管**任一炮塔来提速输出；波次间**自由装配炮塔与装备**，让同一艘飞船一场比一场能扛。本作**没有货币与经济系统**，装备随进度自动解锁。

## 设计主轴（本文件最重要的一条）

> **本作 70% 的乐趣在装配阶段，30% 在战斗阶段。**

- 战斗阶段刻意保持低 APM：不需要持续瞄准，不需要多线微操。
- 装配阶段是本作主玩法：换炮塔类型、装不同装备、针对上一轮暴露的弱点调整。
- 真正的失败模式不是"玩家不动手"，而是**"决策没有意义"**（见 EXPERIENCE 反例）：随机装配的玩家和认真装配的玩家，撑过的危机数应明显不同。

---

## 核心循环

```
【装配 REFIT】← 主玩法
  自由装配炮塔类型与装备 → 预判下一波压力
		↓
【战斗 BATTLE】
  扫视（看主控室常驻的副炮实时画面，判断哪面压力大）→ 接管某一炮塔手动提速
		↓
【危机结束】
  本波敌人清空 → 回到装配
		↓
  循环：装配 → 战斗 → 调整装配 → 战斗
```

- 循环单位是"**危机**"（一波来袭 + 一次休整），不是"开一局"。失败或想重来时，**退回装配界面重打同一艘船**，不换船——培养长期归属感。
- **没有战后修复、没有残骸、没有时间限制**：炮塔每次进入战斗自动满血；装备随危机进度自动解锁。

### 玩家动词（只有 3 个，没出现的一律砍）

| 动词 | 阶段 | 频率 | 说明 |
|------|------|------|------|
| **装配** | 波次间 | 每次危机 1 次 | 换炮塔类型、装装备，本作主玩法，高注意力 |
| **接管** | 战斗 | 每波 0–3 次 | 切换到某炮塔手动射击提速；同时只能操控一个 |
| **扫视** | 战斗 | 低频 | 看主控室副炮实时画面，判断哪面压力大了去接管 |

> 战斗阶段没有"指派""下令""资源管理""走位"。手动接管是**可选的效率提升**，不是必须操作。

## 防御体系：主炮固定 + 副炮可接管

玩家所在的主控室即主炮位置（舰长位），面前是巨大透明舷窗、巨大视角；**控制台在玩家与舷窗之间，控制台上嵌监控屏**，控制台前面才是舷窗（站位修正）。

| 位置 | 防御 | 说明 |
|------|------|------|
| `fore` 前 | **主炮**（固定，不移动） | 默认视角，玩家手动操控主炮时即在此 |
| `port` 左 / `starboard` 右 / `dorsal` 上 / `ventral` 下 | **副炮**（每位置可装多门） | 自动射击（间歇，慢）；**点控制台 feed 或按 1–5** 即可接管切手动提速 |
| `aft` 后 | 推进器高温区 | 无法有效打击，敌人一般不主攻此面 |

- **主炮固定正面，永远不移动、只打正面敌人。**
- 所有炮塔都有**自动 / 手动**两态，且都发射离散弹丸（一发发打，非持续光束）。自动 = 间歇发射 + 系统自动瞄 + 自动算提前量（慢）；手动 = 玩家自己瞄、按扳机发射（提速）。
- 玩家**同时只能手动操控一个**炮塔；其余自动。
- 副炮数量不固定，同一位置可叠加多门（越强越能打，但玩家操控仍只一个）。
- 成长 = 解锁**不同类、不同级、不同功能**的炮塔（速射 / 重炮 / 散射 / 对空 / 对重甲 / 范围…），以及装备槽位的扩展。

## 攻陷 / 失败条件

敌人像海盗，目标是**剥夺星舰的反抗能力再占领它**：把玩家的炮塔全部打掉，星舰就失去了反抗能力。

```
   敌人分头攻击各炮塔（主炮 + 各面副炮）
		↓
   各炮塔逐个被摧毁（每毁一座，该面 / 该组失守）
		↓
   玩家所有炮塔耐久全部归零 → 本局失败
```

- **失败条件是「所有炮塔被摧毁」，不是「主炮被毁即败」**。主炮耐久（150–250）远高于副炮（60–100/门），又是最强的炮，所以**通常它是最后一个沦陷的**——但这只是数值自然结果，不是硬编码规则。
- 没有"舰桥核心 Hull"概念，也没有修复经济、没有自救窗口。
- 失败可清晰归因："我上翼副炮没及时接管被点掉了，最后主炮也扛不住了"。

## 监控系统：常驻副炮实时画面 + 接管时切主视角

> 监控的本质是**补盲**，不是装饰。玩家肉身在舰桥，肉眼只看得见正面舷窗；其余方向靠主控室常驻显示的副炮实时画面掌握战况。

| 原则 | 说明 |
|------|------|
| ① 信息不对称（刚需来源） | 主控室只看得见正面舷窗。左右上下四门副炮的战况，必须靠主控室里**常驻显示**的实时画面才知道。 |
| ② 常驻实时画面（默认形态） | 主控室控制台常驻 **4 块低分辨率、低帧率的副炮实时画面**（SubViewport 渲染），扫视即知哪面有压力。这是「监控只需要简单看一看」的物理实现。 |
| ③ 接管时切主视角 | 玩家决定手动接管某门副炮时，把**主视角切到该炮**去精确射击；松开接管回到主控室。 |

- **性能是真实开销，必须规划**：4 路 feed 不是「切相机零开销」，而是 **4 路额外渲染**（每路一个 Viewport/Camera）。统一压到 **320×180 ~ 512×288、8–12 fps**（扫视用，不需高清高帧），现代机器几乎无感。详见 `04_presentation.md` 第五节与 `03_rules.md` 监控旋钮。
- **不做"六面全息态势图"**（集中总览，常驻 feed 已够用）。2D 雷达总览作为可选补充，非必需。
- 监控屏不是"点扇区指派"界面（主炮不移动、无指派玩法）。
- 验证指标：玩家若全程只盯主炮正面舷窗、从不看副炮画面 → 核心微创新失败，必须重做。

## 关键数值边界（旋钮，终值进引擎调）

> 完整可调旋钮见 `docs/bible/03_rules.md`。本文件只给范围，按知识库第 09 课原则数值外置 `data/*.json`。

| 项 | 值 |
|---|---|
| 攻击方向 | 前 / 后 / 左 / 右 / 上 / 下 六面；`aft` 为高温区 |
| 主炮 | 固定正面 1 组，可多门叠加；**有可见弹丸**（150–250 m/s），玩家接管时**自己**算提前量（`LeadPrediction`） |
| 副炮 | 左右上下，每位置可多门；**同样发射离散弹丸**（一发发打）。自动模式间歇开火（约 3 s 一枪）+ 系统自动锁敌 + **系统自动算提前量** |
| 炮塔双模 | **自动** = 间歇发射 + 系统瞄准；**手动**（接管）= 玩家自己瞄、按扳机发射。接管即提速 |
| 接管输入 | 点控制台 feed 平面，或按数字键 1–5；ESC 回主控室。同时只控一个 |
| 攻陷顺序 | 所有炮塔逐个被毁 → 失败（主炮耐久最高，通常最后沦陷） |
| 副炮耐久 | 60 – 100 / 座（被毁 = 失守） |
| 主炮耐久 | 150 – 250 |
| 主炮弹丸速度 | 150 – 250 m/s（需 `LeadPrediction` 公共函数） |
| 敌人速度 | 小型 14–20 / 中型 9–13 / 重甲 6–10 m/s（慢，刻意） |
| 解锁驱动 | 危机进度（累计度过的危机数）自动解锁，无货币 |
| 单局 / 危机 | 无时间限制；一波敌人 → 休整 → 下一波 |
| 显示分辨率 | 1080p 默认 |
| 模块类型 | 攻击 / 防御 / 机动 / 支援（无能源类） |
