关键约束（来自 turrets.json 的 `_doc`）：**三种是横向差异、不是纵向升级**——总 DPS 守恒（`auto_dps × auto_fire_interval == projectile_damage`），差异只在「单发伤害 / 射速 / 射程 / 耐久」四轴取舍，没有严格最优解。所以视觉上三种应是**同级体量、不同性格**，而不是「越贵越大」。白盒里已经用 `visual_size` + `visual_color` 区分了（见各节），提示词要把这套性格做出来。

## 先说一个提高质量的关键路径

纯文生 3D 几何经常「瘸腿 / 缺面」。你已经在用豆包了，**最优路径是：豆包出一张干净的概念图 → 混元 3D 走 image-to-3D**——比纯文字稳定得多。下面每个炮塔都给了「文生」提示词（兜底用），走图生就把概念图照「造型要点」画出来即可。

> 通用约束（四个炮塔都要）：**不出现任何文字 / 字母 / UI**；**炮口朝相机 +Z 正前方**（导入后旋转对齐到各自扇区）；**硬表面科幻、冷色工业质感**，和主控室 / 敌人同一套美术语言（DEC-025 尺度体系 + 敌人提示词的 gunmetal / dark grey 基调）。
> **友军识别色（设计建议）**：主体是统一友方枪铁灰 / 暗钢，与敌人的**警示红 / 橄榄灰**（敌意）形成一眼可辨的敌我对比；三种副炮再各自用一个**点缀色**区分型号（沿用白盒 `visual_color` 的方向：flak 青蓝 / gatling 琥珀橙 / lance 紫）。这样既认友军、又认型号。
> **尺度（文档未硬规定真实米数，按 `visual_size` 相对比例 + 敌人 6–20 m 自洽推断，见各节）**：炮塔是外挂船体表面的硬表面机械，相对敌人是中小目标。

## 生成完之后的 4 步检查（每个炮塔都要过）

1. **锚定尺度**：导入 Godot 后把最长边缩到 **flak ~3 / gatling ~2.1 / lance ~4.3 / 主炮 6–8 m**——按 `visual_size` 相对比例 + 敌人 6–20 m 自洽推断（DEC-025 尺度体系精神：船外物体尺度要与进场可见度自洽）；文档未硬规定真实米数，可按真船体比例微调。
2. **碰撞用简单体**：炮塔碰撞走 Godot 的 `CollisionShape3D`（球/盒近似），**不拿 AI 生成的网格当碰撞体**。所以网格哪怕非水密也没事。
3. **朝向与扇区**：确认炮口是 +Z；导入后旋转对齐——主炮朝 `fore` 正前，**副炮朝各自扇区外**（`port` 左 / `starboard` 右 / `dorsal` 上）。**底部 `ventral` 没有炮位**（DEC-052：船底留白，着陆面 + 视觉平衡），别为它做第四个朝向变体。接管副炮时你看到的炮塔姿态要和「可转、扫射」对上。
4. **替换占位 + 换外观**：模型挂到 `TurretSystem` 的 spawn，换掉现在的占位 Mesh（清单工程通则第 4 条）。三种副炮各有专属外观（按本文件生成）；`swap_turret()` 已支持按 variants 整体替换数值 + 外观（`visual_color` / `visual_size` 即换装时的差异来源），无需为型号另建骨架。
