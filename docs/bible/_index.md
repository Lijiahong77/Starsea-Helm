## 阅读顺序（给人看的，约 80 分钟）

第一批看完就能判断"方向对不对"，第二批看完就能拍板，三四批开工前再看。
每份文件建议**带着一个问题读**，读完能回答就够了 —— 不必逐字通读。

## 本项目的三条最高宪法（AI 必读）

1. **主轴**：70% 乐趣在改装阶段，30% 在战斗阶段。战斗刻意低 APM，「挂机感」是目标不是缺陷。
   → 真正的失败模式是「**决策没有意义**」，不是「玩家不动手」。（DEC-021）
2. **不要照抄知识库里的具体游戏案例**。知识库提供流程（三问法 / Bible / P0–P3 / 一次只改一件事），
   其中的弹珠肉鸽、Vampire Survivors、Brotato 等**只是教学示例**。（DEC-023）
3. **数值只给旋钮不给终值**，一律外置 `data/*.json`，禁止 hardcode。（第 09 课）

## Context Prelude（复制到每次 AI 会话开头）

```
你正在协助开发一个 Godot 4.7 的第一人称太空舰桥塔防游戏（Starsea Helm / 星海舵手）。
项目位于 D:\GameProject\Starsea Helm，Bible 位于 docs/。

开始任务时：
1. 先读 docs/bible/_index.md，提取本次涉及的文件路径清单
2. 根据任务只读最相关的文件，不要一次读全部
3. 复述你对当前任务的理解，先不要写代码
4. 涉及新实体 → 02_entities.md；调数值 → 03_rules.md；改玩法流程 → 01_core_loop.md
5. 建场景 / 调相机 / 改舱室 / 碰渲染 → 04_presentation.md
6. 命名与事件规范查 MODULES.md 第三节
7. 数值一律外置到 data/*.json，禁止 hardcode 到脚本
8. 一次只改一件事（知识库第 09 / 12 课铁律）

呈现边界：**战场是 3D 的，界面是 2D 的。** 舰桥/敌人/炮塔/主炮弹道是 3D；
雷达屏、改装界面、HUD 是 2D Overlay UI；控制台上的副炮实时画面是 Viewport 贴图（3D 世界屏）。监控 = 主控室常驻 4 路副炮实时画面（SubViewport 渲染，低清低帧）+ 接管切主视角；真实多视口开销但可控（DEC-039）；不做六面全息图。

核心设计（2026-09-01 重定位）：
- 循环 = 装配 → 战斗 → 调整装配 → 战斗，单位「危机」；无经济、无修复、无时间限制
- 主炮固定正面；副炮四向可多门。**所有炮塔统一「自动 / 手动」双模，且都发射离散弹丸**：
  自动 = 间歇发射（副炮约 3 s 一枪）+ 系统自动锁敌 + **系统自动算提前量**；手动 = 玩家自己瞄、按扳机发射
  主炮弹丸慢（150–250 m/s），玩家接管时**自己**算提前量（`LeadPrediction`）
- 接管输入 = **点控制台 feed 平面，或按数字键 1–5**（双保险）；**ESC 回主控室**；同时只手动操控一门
- 失败 = 所有炮塔被摧毁（主炮耐久最高、通常最后沦陷；无 Hull、无自救）
- 70% 乐趣在装配阶段，战斗刻意低 APM；失败模式是「决策无意义」而非「玩家不动手」

本作三条最高宪法：
- 70% 乐趣在改装阶段，战斗刻意低 APM；失败模式是「决策无意义」而非「玩家不动手」
- 知识库只学流程，不照抄其中的具体游戏案例
- 数值只给旋钮，不给终值
```
