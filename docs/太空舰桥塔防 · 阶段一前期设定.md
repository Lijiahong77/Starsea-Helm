# 太空舰桥塔防 · 阶段一前期设定

严格遵循知识库「阶段一・基础入门」方法论，从核心定位、可行性评估、轻量文档、引擎选型到里程碑规划完整落地，全程预留 VR 迁移架构空间。

---

## 一、核心定位：三问法锚定 \+ 微创新（对应第 01 课）

### 三问法（唯一筛选标准）

1. **玩家在做什么？**（核心动词）
切换全域监控画面、手动操控主炮、更换飞船模块、调度系统状态，抵御一波波外星敌袭，守护自己的星际战舰。

2. **玩家感觉像谁？**（核心幻想 / 身份）
孤身深空战舰的舰长，在主控室里靠多屏监控与策略决策掌控整艘飞船，既是全局指挥官，也是一线操作员。

3. **2 周内能做完吗？**（MVP 时间盒）
完全可以。MVP 限定单主控室场景、4 个核心系统、基础敌袭循环、核心监控交互，工作量严格控制在 2 周周期内。

### 微创新定位（X\-like \+ 一条微创新规则）

- 基础原型：**第一人称太空塔防**

- 核心微创新：**全域监控舱室操作**—— 把传统塔防 “在场外建防御塔” 替换为 “舰内监控视角下的模块改装与系统调度”。玩家全程身处主控室，通过多机位摄像头 \+ 顶视合成图掌控全局，策略改装与手动操作深度结合，打造「人舰一体」的沉浸感。

## 二、方向可行性评估（对应第 01 课评估模板）

按 5 个维度 1\-5 分打分：

|维度|得分|核心理由|
|---|---|---|
|实现容易度|4|固定第一人称主控室场景，无需大世界移动；监控系统为 UI \+ 摄像机切换逻辑，塔防 AI 成熟；整体复杂度低，适合快速原型验证|
|体验清晰度|5|「舰长 \+ 主控室 \+ 监控管全船」身份感极强，目标直白明确，第一人称 \+ 多屏监控的代入感直接且强烈|
|美术类型匹配度|4|科幻舱室 \+ 太空背景，用基础 3D 几何体 \+ 发光 UI / 屏幕即可出硬核氛围，不需要高精度模型与复杂场景|
|传播潜力|4|「第一人称舰桥监控塔防」差异化记忆点强，「后续可转 VR」自带话题性，人舰一体的设定易传播|
|微创新潜力|5|监控调度 \+ 模块改装 \+ 手动操作的组合有大量深挖空间，可扩展宇宙事件、全舰系统、VR 深度交互等内容|

总分 22/25，属于非常适合快速做 MVP 验证的优质方向。

## 三、轻量文档架构（对应第 02 课）

原型阶段采用「SPEC / MODULES / EXPERIENCE」轻量架构，不写完整 GDD；后续模块超过 8 个再升级为分片式 Game Bible。

```Plain Text
docs/
  ├── SPEC.md       # 游戏是什么、不是什么
  ├── MODULES.md    # 模块拆分与职责
  └── EXPERIENCE.md # 体验目标与反例
```

### 1\. \[SPEC\.md\]\(SPEC\.md\) 核心内容

- **One\-liner**：第一人称舰桥视角的太空塔防游戏，玩家通过全域监控系统掌控全舰，手动主炮 \+ 自动副炮抵御敌袭，波次间更换模块强化飞船。

- **核心循环**：敌袭预警 → 全域监控态势 \+ 主炮手动射击 \+ 副炮自动拦截 → 波次间隙更换模块改装 → 下一波敌袭

- **关键数值边界**：飞船初始 100 护盾值，主炮单发伤害 15，2 种基础敌人，波次难度递增，3 类基础改装模块

- **Non\-goals**：不做开放世界自由航行、不做 VR 实装功能、不做剧情与角色、不做完整八大系统、不做非战斗类宇宙事件、不做多人与存档

### 2\. \[MODULES\.md\]\(MODULES\.md\) 模块拆分（无循环依赖）

|模块|职责|输入|输出|依赖|
|---|---|---|---|---|
|MonitorSystem|全舰摄像机切换、顶视合成图生成、态势标记|玩家操作、飞船状态、敌人位置|监控画面、顶视全息、目标标记|ShipSystem、EnemySystem|
|PlayerController|第一人称视角控制、主炮瞄准射击、物理按钮交互|鼠标 / 键盘输入|视角旋转、主炮炮弹、交互事件|无|
|WeaponSystem|主炮 / 副炮逻辑、自动索敌、伤害计算、过热管理|玩家射击指令、目标位置、模块属性|炮弹实体、伤害事件、过热状态|EnemySystem|
|ShieldSystem|护盾值管理、伤害减免、受损反馈|伤害事件、模块属性|护盾状态、受损特效|ShipSystem|
|EnergySystem|全舰能源分配、模块供电、过载判定|模块配置、操作指令|能源状态、过载警告|ShipSystem|
|EnemySystem|敌人生成、移动逻辑、波次调度|波次配置|敌人实体、撞击伤害事件|无|
|ShipSystem|飞船整体状态、模块槽位管理、属性汇总|模块配置、伤害事件|飞船全局状态、死亡事件|无|
|UISystem|监控屏 UI、改装界面、HUD 信息、状态提示|玩家操作、飞船状态|界面交互、配置变更|MonitorSystem、ShipSystem|
|VFXSystem|射击、爆炸、受创、屏幕特效|射击 / 伤害事件|视觉特效表现|无|

### 3\. \[EXPERIENCE\.md\]\(EXPERIENCE\.md\) 体验定义

- **体验关键词**：沉浸掌控感、硬核科幻感、策略调度感、紧张战斗感

- **关键时刻**：切监控精准拦截敌机的爽感、波次间选模块的决策感、残血极限守船的紧张感、顶视全局调度的掌控感

- **反例**：不做成纯 FPS（火力碾压无需策略）、不做成纯挂机塔防（玩家无操作空间）、不做复杂跑图（主控室完成所有操作）、不做繁琐模拟（系统自动运行，手动是增强而非必须）

## 四、引擎选型与 VR 预留架构（对应第 03 课）

### 首选引擎：Godot 4\.x（4\.3\+）

完全匹配知识库推荐，且完美适配你的 VR 远期规划：

1. 3D 节点式架构适合模块化飞船与舱室场景，快速堆叠原型

2. GDScript 语法类 Python，对 AI 友好，可通过 MCP 工具链高效开发

3. 轻量启动快，2 周 MVP 迭代效率最高

4. **核心优势**：Godot 4 原生支持 XR/VR，后期只需添加 XR 节点、替换输入系统即可迁移，改造成本极低

### VR 预留架构原则（现阶段只规范、不开发）

为保证后期无缝转 VR，现阶段代码严格遵守**输入层与逻辑层完全分离**：

1. 所有操作（开火、切屏、按按钮、换模块）全部封装成独立接口（如`FireMainGun()`、`SwitchCamera(index)`），不直接绑定鼠标按键

2. 主控室内的屏幕、按钮、拨杆全部做成 3D 物理可交互物体，而非平面悬浮 UI

3. 所有可交互点位预留 Transform 坐标，未来 VR 手部射线 / 物理按键可直接复用

4. 视角旋转逻辑用「视角目标」驱动，不写死鼠标控制

5. 顶视全息、监控画面都渲染在 3D 平面上，而非 Overlay 层，VR 中可自然观察

## 五、两阶段开发里程碑（对应第 04\-05 课）

严格遵循「先 Prototype 验证技术，再 MVP 打磨体验」的顺序，2 周走完完整闭环。

### 里程碑 1：Prototype（3\-4 天，技术验证）

**验收标准**：跑得通、核心逻辑成立、无严重卡顿

1. 搭建白盒主控室场景（立方体舱体 \+ 正面舷窗 \+ 中央控制台）

2. 实现第一人称鼠标视角控制，可转头观察舱内与窗外

3. 完成主炮基础逻辑：左键瞄准射击、生成炮弹、碰撞检测

4. 最简单敌人：从屏幕外直线飞向飞船，撞击扣除护盾值

5. 基础监控系统：2 路外部摄像头切换 \+ 简易顶视合成图

6. 验证点：能瞄准击毁敌机、飞船会扣血、监控可自由切换

### 里程碑 2：MVP（剩余 10 天，完整体验闭环）

**验收标准**：玩家玩 3 分钟还想再来一局

#### P0 必须实现（不做就不是这个游戏）

- 完整全域监控系统：多机位切换、顶视态势全息、点击目标自动锁定

- 自动副炮系统：2 座舷侧副炮，自动索敌射击，属性绑定模块

- 波次系统：无限波次难度递增，2 种基础敌人（小型战机 \+ 中型轰炸机）

- 模块改装系统：波次间开启，攻击 / 防御 / 能源 3 类模块，对应槽位替换

- 飞船状态系统：护盾值、能源值、受损反馈、死亡结算

- 基础 HUD 与状态提示：护盾、波次、能源、系统警告

- 胜负结算界面与重开功能

#### P1 优先实现（核心乐趣更完整）

- 主炮过热机制：增加射击节奏与策略性

- 3 个基础舰长技能：战斗警戒、全舰过载、紧急规避

- 基础射击、爆炸、受创特效与太空背景

- 模块等级差异：同模块分基础 / 进阶两级

#### P2/P3 全部砍掉（后续版本再做）

- ❌ 动力航行、无人机、生命维持等其余系统

- ❌ 宇宙天体现象、探索残骸等非战斗事件

- ❌ 船坞改装过场动画、飞船外观变化

- ❌ 剧情、成就、存档、多关卡

- ❌ VR 实装功能
