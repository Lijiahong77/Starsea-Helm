# 功能清单与优先级（P0–P3）
> 按知识库第 05 课方法拆解。最后更新：2026-09-10（**⑪ 第一层落地，DEC-047**：手感参数走「事件→强度表」+ 三层分工；闪白/震屏/推镜已通。P0 仅余 ⑪ 后三层 + ⑥ 冻结）
> **P0 = 不做就不是这个游戏｜P1 = 做了核心乐趣才完整｜P2 = 更好玩｜P3 = 更高级，删了不影响核心**

> 排序依据：**是否唤起核心乐趣**。本作核心乐趣 = 「战损驱动的改装决策」+「接管任一炮塔的临场提速」。

## P0 · 不做就不是这个游戏

| 功能 | 优先级 | 一句话理由 |
|------|--------|-----------|
| 第一人称主控室（可转头看 + **仅艏部单面舷窗**） | P0 | 第一人称是微创新的载体；**单面舷窗是 DEC-026 的物理保证**，第一天就要做对 |
| 六扇区划分与威胁计算（`aft` 为高温区基本不含） | P0 | 分路来袭是据点防守基因 |
| 主炮固定正面（1 组，可多门叠加，有弹丸 + 提前量） | P0 | 默认视角，玩家手动操控主炮时即在此 |
| 四向副炮（左右上下，每面可多门）自动慢速开火 | P0 | 刻意自动化，把注意力还给决策 |
| 手动接管任一炮塔提速（同时只控一个） | P0 | **战斗阶段核心决策**：把火力用在正确的地方 |
| 炮塔耐久 + 被毁 + 每波满血复位 | P0 | 攻陷链基础，失败可归因的前提 |
| **所有炮塔被毁 = 本局失败**（主炮耐久最高通常最后沦陷） | P0 | 终局条件（DEC-037） |
| 敌人生成 / 移动 / 扇区归属 / 攻击最近炮塔 | P0 | 没有威胁就没有游戏 |
| 波次调度与难度曲线（无时间限制） | P0 | 波次生存的定义 |
| 监控系统（**副炮视角切换**为主；雷达仅退回） | P0 | **核心微创新**，不看监控就没有理由做第一人称 |
| 改装阶段：换炮塔类型 / 扩展槽位 | P0 | **主玩法**，战损驱动的落点 |
| 自动解锁（随危机进度解锁新炮型 / 新槽位） | P0 | 成长感来源，无货币（DEC-033 / DEC-042） |
| 状态机（REFIT / BATTLE / RESULT） | P0 | 闭环骨架 |
| EventBus / GameStateManager | P0 | 架构地基，后补代价极高 |
| AudioManager（骨架 + 核心音效） | P0 ✅ | 知识库第 10 课：后期加满会到处打补丁。**已落地 16 音效 + 3 BGM 位（DEC-046）** |

## P0 收尾后的头号重点（2026-09-09 李定）

P0 全部 ✅ 之后，**最要紧的是把美术资产方案定下来** —— 这是后续 P1 / P2 的地基。

- **谁主导**：李（具体方案讨论项由他拍板）；AI 协助清单 / 候选 / 对比。
- **范围**：按 bible `04_presentation` 的替换顺序 —— 舱室 → 控制台 → 敌人 → 炮塔 → VFX。
- **首要解的锁**：**⑥ 监控接真副炮冻结**（DEC-038，等模型定尺寸）—— 模型一确定，⑥ 解冻、`monitor_feed.md` 的快照才有的放矢。
- **AI 边界**：定方向、找候选、写对比表 → AI 擅长；具体风格定稿、选型决定、商业资源谈判 → **不在 AI 范围**。

## 开发顺序建议（一次只做一件事）

```
① Godot 工程初始化 + 舰桥舱室（CC0 素材占位 · 单面舷窗）+ 第一人称转头   ← 开工第一天
② EventBus / GameStateManager 骨架
③ 六扇区 + 敌人生成与移动（不做开火）
④ 炮塔开火（先做副炮自动，再做主炮固定 + 接管）· 主炮必须做提前量预测 LeadPrediction
⑤ 炮塔耐久 + 被毁 + 所有炮塔被毁=失败 + 结算
⑥ 监控（先实现副炮视角切换；仅当实测有性能问题才退回雷达）
⑦ 改装阶段：换炮塔类型 / 扩展槽位（先跑通装配闭环）
⑧ 自动解锁（随危机进度）
⑨a 战损报告（一套数据、四个出口：主控室/维修站/维修师台词/改装台）
⑨b 陷落演出三级分层（L1 单炮计数 / L2 该面红叉 / L3 终局夺镜）
⑩ 音频骨架
⑪ Game Feel 五层 + VFX（一次一层；VFX 已并入）
```

> 每一步做完都要 F5 自测至少 1 分钟再进入下一步（知识库第 09 / 12 课）。
> 性能调研（多路 SubViewport）**已随六面全息图删除而不再需要**（DEC-038）；若副炮视角实测有卡顿，按「退回雷达」处理，不要第一天就纠结渲染架构。
