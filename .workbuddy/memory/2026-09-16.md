## 舱室渲染方案定调：内外分离，船壳剔除不承重（咨询，未改码）

**背景**：李拿到 `assets/models/AISpaceship_3.glb`（+ PBR 三张贴图，已带 .import），
问「把房间放进模型内部、把船壳改成单面/通透渲染，让玩家在里面能看到外面」是否可行、会不会埋雷。

### 结论（四条，按重要性）
1. ⚠ **【本条已被探针推翻，勿采信 → 见文末「探针实测」】原写：船壳从内部透明 = Godot 默认行为，不用做任何设置。** glb 导入的材质默认 `cull_mode = back`
   （证据：`docs/ASSET_WISHLIST.md:21` 自己记的坑「外部模型法线朝外，从房间里看会整面透明」）。
   → 想要的效果已经免费拿到。
2. **真正挡视线的是「房间内胆墙」，不是船壳。** 内胆要**双面**（或法线朝内）才挡得住。
   船壳剔除（back）与内胆双面（disabled）**要求相反** —— 这恰好证明二者必须是**两套几何**。
3. **⚠ 只靠船壳透明 = 玩家 360° 全看穿 → DEC-026 当场失效，且不报错。**
   这是本次咨询最重要的风险提示：承重墙从「物理几何保证」被降级成「一个材质设置」，
   哪天换材质/美术在 Blender 翻法线就静默崩塌。**别把它当遮挡机制。**
4. **选背面剔除，别选 alpha 半透明。** 半透明会与舷窗玻璃、星空 shader、日后护盾/VFX 抢排序（穿模）；
   剔除是不透明材质少画一半面，无排序问题、性能最好。

### 工业界标准解：interior/exterior split
内外双几何（外壳给舰外/远景/副炮接管，内胆给舱内）+ **相机 cull_mask 分层** + 真实遮挡体。
案例：《星际公民》《精英危险》《无人深空》；Unreal Room Visibility / Source Portal。

| 层 | 主控室相机 | 舰外相机（DEC-050/051 副炮接管） |
|---|---|---|
| 外壳层 | 跳过 | 渲染 |
| 内胆层 | 渲染 | 跳过 |
| 世界层（星空 + 敌人） | 渲染 | 渲染 |

### 其他提醒（未落文档）
- 舷窗外是 **shader 程序化星空**（bible §一）→「看得见外面」与船壳透不透明**无关**。
- 剔除**不影响光照**：内景必须独立布光，否则全黑或被外部天光污染；船壳若 cast shadow 阴影仍残留。
- 船壳材质与内胆材质**不能共用**（cull 设置相反）。
- 主炮接管「准星夹在窗洞内」的数学依赖**真实几何窗洞**（前墙 4 块拼），不能靠剔除假装。
- 碰撞不受剔除影响（`CollisionShape3D` 独立）——这条不用担心。

## 探针实测 `AISpaceship_3.glb`（工具：`docs/tools/_probe_glb.py`）

新增工具：**不启动 Godot/Blender 直接读 glb 的 JSON chunk**，拿包围盒/节点树/材质 doubleSided/面数。
以后每来一个模型都先跑它，别靠猜。

### 🔴 推翻上一条结论的事实
- 模型材质 `Material.001` = **`doubleSided: True` / alphaMode OPAQUE**。
  → Godot 导入后 `cull_mode = 关闭（双面）` → **从内部看船壳是不透明的实心壁**。
  → 玩家透过舷窗看到的是**船壳内壁**，不是外面的星空。**必须改材质**，不能"什么都不做"。
- 改法二选一：(a) Blender 里材质勾 Backface Culling → 重导（源头干净，但要再提交 65MB）；
  (b) Godot「Advanced Import Settings」把该材质 Cull Mode 改成 Back（写进 `.import` 的 `_subresources`，不动源文件）。
  **推荐 (b)**（不用重传 65MB，且 `.import` 是文本、可版本控制）。

### 🔴 尺度差 57 倍
- 模型世界包围盒：**1.118 m（长） × 0.787（宽） × 0.355（高）**，最长边 1.12 m。
- `.glb.import` 里 `root_scale=1.0 / apply_root_scale=true` → 导入即 1:1 → 会得到一只 1 米的玩具船。
- 目标船长 64 m → 需缩放 **×57.2**。

### 🔴 长宽比与项目规格冲突（需李拍板）
| | 模型（长归一） | `presentation.json` / `04_presentation.md` |
|---|---|---|
| 长 | 1.000 | 1.000 |
| 宽 | **0.704** | 0.344（22/64） |
| 高 | **0.318** | 0.250（16/64） |

等比缩放到长 64 → **64 × 45 × 20 m**。而 `hull_radius = width/2 = 11` 是所有炮塔挂载/扇区公式的根
→ 宽改 45 则 `hull_radius` 应变 22.5，牵动炮塔挂载、扇区判定、难度（周长翻倍）。
> ⚠ 另注：包围盒的"宽"很可能是**翼展**（翼尖到翼尖），不是船体核心宽 —— 定 `hull_radius` 前要看形状。

### 🟡 其他
- 单节点 / 单网格 / 单材质（`node_0 [mesh 0]`, t=0 s=1）→ **整船一个 mesh**，无法分件隐藏；
  分层只能整体给一个 layer（对内胆/船壳分层方案反而更简单）。
- **50 万三角面**（321,834 顶点 / 499,536 面）。舰外相机 + 4 路监控 SubViewport 都渲染它时要注意预算。
- 包围盒 z 不对称（+Z 侧 0.692 / -Z 侧 0.426）→ **船头朝 +Z 还是 -Z 待确认**（探针看不出）。
- `.import` 里 `meshes/light_baking=1`（静态光照贴图）+ `create_shadow_meshes=true` → 动态飞船建议关掉 light_baking。
- **仓库体积**：`assets/models/` 合计 **115 MB**（glb 65.3 + basecolor 22.3 + metalrough 16.4 + normal 11.1）。
  `.gitattributes` 只有 `*.glb binary`，**没有 LFS** → 每次改动都翻倍进 Git 历史。建议上 Git LFS 或压贴图。
