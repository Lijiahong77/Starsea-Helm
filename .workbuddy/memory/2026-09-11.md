## 李实机试玩复盘 → 本轮只做「非美术三条」（DEC-048）

原报 9 条问题，本轮按李拍板的边界**只动三条与美术无关的**，美术（建模 / 音色 / VFX）等资产到位再说。

1. **受击反馈阈值化**（李点名的"震屏 + 音效过大"真凶）
   - 根因：`Turret.take_damage` 被敌人**每物理帧**调用（持续 dps）→ `turret_damaged` 每帧发 →
     GameFeel 每帧重置震屏计时（有任何敌人啃着就永远停不下来）+ 音频 250ms 窗口连成持续蜂鸣。
   - 修法：新增**离散**信号 `EventBus.turret_critical`（耐久**首次**跌破 `presentation.json` 的
     `feel.critical_ratio = 0.3`），`Turret._check_critical()` + `_critical_fired` 保证一波只发一次，
     `restore()` 重置。`turret_damaged` **保留但明确降级为记账流水**（DamageLog 用），接反馈即噪音。
   - 旋钮：`FeelKit.critical_ratio()`、`feel.events.turret_critical.shake`、`audio.json` 的
     `sfx_turret_critical`（方波 760Hz，limit_ms=0 不走限流）。
   - 防静默回归：feel 探针加了**反向断言**（`turret_damaged` 必须不出现在 `feel.events` 里）。

2. **交互「看」与「打」分离**（数字键切视角导致玩家被拽进战斗）
   - 新增 `TurretSystem.current_view_id`，与 `current_manual_id` **彻底分成两个状态**。
   - 数字键 1-5 = `focus` / `focus_sector`：**只搬镜头，炮塔照常自动开火**（不改变火力模式）。
   - **鼠标右键** = `takeover_focused()`：接管 / 释放当前视角（在舰桥没聚焦时默认主炮）。
   - ESC 三级：先释放接管 → 视角回主控室 → 退出。
   - 新信号 `turret_view_changed`，顺手删掉**零订阅零发射**的僵尸信号 `monitor_view_changed`。

3. **维修师台词重写**
   - 身份对齐：名字"老陈"→**驻站技师**；玩家 = **跑货运的舰长**，**每次停靠的是不同的站**。
   - 删除熟人腔 / 战斗指挥腔 / 教玩家怎么玩；7 组台词（open/repair/ask/farewell/unlock/unlock_slot/damage）全改。

- 证据：**11 套 422 断言全绿**（feel 56 · audio 63 · healthbar 43 · round2 21 · turret_hp 30 · enemy 15 ·
  wave 25 · refit 33 · unlock 81 · damage 37 · collapse 18）；主场景 headless 0 脚本错误。
- 回填：`docs/MODULES.md §3` 信号表 + 扇出表 · `docs/bible/99_decisions.md` DEC-048 · `docs/BACKLOG.md` ④⑦⑧⑪ 行 · 专册 `game_feel.md`。

## 敌人飞行 → 李拍板 **A 方案**，结构 + 行为两阶段都已落地（DEC-049）

- 李的认知是「大类 `Enemy` + 子类继承」。**不算错**，但对「飞行方式」这一层不划算 ——
  **型号 × 飞行行为是两个独立的轴**，继承树一次只能沿一条切分（画了 3×3 网格：现役三型各占一格，
  而「重甲 + 突进」这类跨行组合在树里没安放点）。
  三方案：**A 数据 + 行为函数分发**（选它）/ B 数据 + 策略类（行为 >5 种或词条要改飞行时再上）/
  C 继承（只在"完全不同的实体类型"如无人机群、导弹时才开子类）。
- **Phase 0（结构，表现零变化）**：① `flight_<type>` 外置 + 补 `dps_heavy`；
  ② `_stopped` → `_engaged`，新增 `is_engaged()` / `velocity()`，`is_hovering()` 缩窄为"是否静止"；
  ③ `advance()` 把位移交给 `_step_flight()`，只有 `_fly_hold()`，**与拆分前逐帧等价**（回归全绿即证据）。
- **Phase 1（行为）**：小型 `orbit` = 绕飞船画圈，半径恒 = `attack_range`（李拍板"贴着绕"）；
  中型 `strike_retreat` = **反复来回的进攻航线**（李纠正：不是"逃跑"，是飞来飞去地进攻）。
  每一步「加一种飞行」= 一个 `_fly_xxx()` + JSON 一个值。

### ⭐ 两个"以为简单、其实有隐藏前提"的发现

1. **`is_hovering()` 是承重墙**：`Turret.acquire_target()` 用它筛目标 = **自动开火只打"悬停"的敌人**。
   绕飞 = 永不静止 → 自动炮**一架都锁不上、全船哑火**且不报错。根因是这个名字把
   「到了攻击距离（能不能锁）」和「停下不动（动不动）」挤成一件事。
   → 准则：**表达"能力/资格"的判据必须与表现形态解耦；表达"状态"的才归表现层**。
2. **自动开火根本不算提前量**：原注释「敌人悬停时不需要 LeadPrediction」是 **hold 唯一存在时的结论**，
   不是普遍规律。敌人一动就系统性打空（弹丸飞 52m ≈0.26s，目标横移数米，hitbox 才 6~14m），
   表现是「炮一直在响、敌人血不掉」。已改为有速度就算提前量（对 hold 逐帧等价）。
- 附带修的：`_stats_for` 类型塌陷（heavy 静默拿拦截机数值）；提前量从"推方向"改"采样真速度"；
  `bridge_whitebox` 里那份 hardcode 的船心删掉。
- **护栏有效性也实测**：故意把 `flight_bomber` 改成 `"oribt"` → 明确 WARNING + 退回 `hold` +
  `enemy_test` 变红 29/1，随后恢复。**永远为真的断言不是护栏**。

- 证据：`enemy_test` **39/39**（+24）；回归 **11 套 / 446 断言全绿**；主场景 headless 0 错误 0 告警。
  实测：绕飞 2 秒位移 32.7m 且半径 51.7→51.7 守恒；巡航 100 秒进出 5/4 轮、掠过最近 29.1m。
- ⚠ **待李实机验证的两个副作用**（选择的代价，不是 bug）：① 绕整船一圈会**跨扇区**
  （扇区压力会转移）；② 伤害会**摊到沿途各门炮**，削弱「某一门先废掉」的具体性（DEC-043 靠这个）。
  旋钮顺序：先调小 `orbit_speed_factor`，再不行把 `flight_interceptor` 改回 `hold`。
