## 循环（单位 = 危机，不是「开一局」）
`REFIT(装配·无时限·主玩法) → BATTLE(一波) → REFIT … → 全部炮塔被毁 → RESULT → 再来（同一艘船，解锁保留）`
玩家只有 3 个动词：**装配 / 接管 / 扫视**。没有移动、没有资源管理、没有下指令、没有主动技能。

## 扇区（6 面）
| ID | 常驻防御 | 舷窗可见 | 备注 |
|----|---------|---------|------|
| fore | 主炮（固定） | ✅ | 唯一肉眼可见的战场 |
| aft | 无 | ❌ | 推进器高温，敌人基本不来 |
| port / starboard / dorsal / ventral | 副炮（每面可多门） | ❌ | 只能靠监控/雷达 |

## 炮塔
- **主炮** 1 组，只打 fore。耐久 150–250，伤害最高，通常最后沦陷（数值自然结果，**不是硬编码规则**）。发射**离散飞行弹丸**（150–250 m/s）→ 手动瞄准需提前量。
- **副炮** 四向，每面 0–N 门，耐久 60–100/门。全灭 = 该面失守（breached）。
- 两态：**自动**（慢、间歇，副炮约 3s 一发，自动瞄准，拖得住赢不了）/ **手动**（玩家接管，射速大幅提高，**同时只能接管一门**）。
- 每波开始所有炮塔自动回满耐久（无维修经济）。实现在 `TurretSystem.set_battle_active(true)` 内部。
- **失败条件 = 所有炮塔被毁**（DEC-037）。无 Hull、无护盾。
- **⑤ 已接（2026-09-07）**：敌人悬停后按 `dps × delta` 持续伤害**最近存活**炮塔；
  旋钮 = `enemies.json` 的 `dps_interceptor=3` / `dps_bomber=7`（波次压力主旋钮）。
  被毁 → 停火 / 不可接管 / `sector_breached`；全毁 → `all_turrets_destroyed` → RESULT。
  ⚠ **未决几何问题**：bible 的「最近」没限扇区，实测 fore 来袭的轰炸机先啃 dorsal
  （49.6m > 主炮 51.2m 的反超），与主炮「通常最后沦陷」的预期冲突。待手感实测后裁决
  是否改成「优先本扇区、无存活炮塔才跨面」。
- 类型（按危机数自动解锁，无货币）：速射 / 重炮 / 散射 / 对空 / 对重甲 / 范围。成长也来自解锁**额外槽位**（同面叠炮）。
- **⑦ 改装已接（2026-09-08，DEC-041）**：4 门副炮可换 3 种型号（`turrets.json` 的
  `variants`），**横向差异不是纵向升级** —— 总 DPS 守恒（`auto_dps × interval == 单发伤害`），
  差异在射速/单发/射程/耐久四轴：flak 3s-24dmg 均衡 / gatling 1.5s-12dmg 抗集群 /
  lance 4.5s-54dmg 一发秒轰炸机但怕集群。**主炮固定不可换**（DEC-030）。
  改装在**维修站过场**里（清空一波自动触发）：黑屏飞站 → 维修师台词**纯氛围不涉钱**
  → 改装台选槽位选型号 → 出发。过场任意键快进当前段，**不给跳过按钮**。

## 波次（⑨ 已接，2026-09-08）
- **一次全出**（用户拍板）：进 BATTLE 时整波一起 spawn。靠 190m 飞行时间天然形成
  bible 的预警(8s)→接敌→交战→清场 四子阶段，因此**没有批间隔 / 批次**概念。
- 组成 = `compose(wave_index)`（WaveSystem 里的纯函数，可直接断言）：
  总数 `min(base + (n-1)×growth, max)`、bomber 占比从 `bomber_start_crisis` 起缓升到封顶。
  **旋钮全在 `data/waves.json`**（首波 4 / 每波+1 / 上限 20 / 第 4 波起掺 bomber / 比例 0.15→0.6）。
- 清空 → `crisis_cleared`+1 → 自动回 REFIT；离开 BATTLE **清场**（否则残留敌人 +
  反复按 B 回满耐久 = 无限续命，⑤ 的失败条件失效）；RESULT 后 wave_index 归零。
- **清空只数自己 spawn 的**（自存名单，不用 `enemy_count()`）—— E/R 调试键生成的
  敌人不参与波次，否则按几下 E 本波永远清不空。

## 敌人
外缘生成 → 直飞 → 进入攻击距离（45–60）持续伤害最近存活炮塔 → 该炮塔死则改打下一个最近的。
速度刻意偏慢（6–20 m/s）。三种：拦截机（快脆多）/ 轰炸机（慢厚、对炮塔伤害高）/ 重甲（极厚极慢，P1）。

## 监控（微创新载体）
主控室常驻 **4 路副炮实时画面**（SubViewport，320×180~512×288 @8–12fps）+ 接管时切主视角；2D 雷达仅作性能退回。**不做六面全息图**。
舰桥只有艏部一面舷窗 —— 信息不对称由物理保证（DEC-026）。

## 尺度（1 unit = 1m）
舰桥 6×5×3、眼高 1.6、飞船 64×22×16、进场半径 150–190、攻击距离 45–60。
相机 FOV 70、pitch ±80、yaw 360、无 head bob。渲染器 **Forward+**。

## 架构
- autoload：`EventBus` / `GameStateManager`(REFIT·BATTLE·RESULT·MENU) / `AudioManager`。
- 业务层：Ship / Turret / Enemy / Wave / Monitor / PlayerController / Refit / UI 系统（VFX P1）。
- 全部经 **EventBus** 通信，**禁止系统间直接互调**；事件命名 `domain:past_tense_event`。
- 搁置/已删：TacticalOrderSystem(P2)、EconomySystem(删)、ShieldSystem(删)、弱点、三选一构筑、悬赏、Hull、过热冷却。

## 验证指标（Prototype / MVP）
3 分钟复玩意愿 · 首次失败可归因（"我上翼副炮没接管"）· 装配停留 45s+ · **随机 vs 认真装配存活危机数差 ≥ 3**（DEC-021，立项假设）· 副炮视角使用频繁。
