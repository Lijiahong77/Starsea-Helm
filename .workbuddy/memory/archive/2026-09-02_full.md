# 2026-09-02

## 修复：监控屏幕中心 ≠ 摄像机画面中心（根因 = BoxMesh UV 图集）

**现象**：编辑器 Camera Preview 里标记方块在正中心，但主控室监控屏幕上方块偏离中心。

**根因（headless 逐顶点 dump 实测，非猜测）**：Godot 4 的 `BoxMesh` 用 **3×2 UV 图集**，6 个面各占 UV 空间的 1/3 × 1/2。
屏幕原用 `BoxMesh(0.5,0.375,0.02)`，其正面（法线 +Z）UV 区间只有 **(0,0)..(0.3333, 0.5)** = 整幅画面的左上角 1/3 宽 × 1/2 高被拉满整屏 → 画面中心 uv(0.5,0.5) 落到屏幕右边缘之外。

**修法**（完整细节见 `godot_pitfalls.md` 第 3 节）：
1. 屏幕网格 `BoxMesh` → **`QuadMesh`**（朝向/法线/uv 原点与 BoxMesh 正面一致，UV 全幅，可直接替换，无需改 transform）。
2. **运行时重建网格**（`_layout_screens()`），免疫编辑器回退 `.tscn`。
3. 网格长宽比 == feed 分辨率长宽比 → 等比铺满、中心对中心。
4. 材质显式归位 `uv1_scale=(1,1,1)` / `uv1_offset=(0,0,0)`。

**数据改动**：`data/presentation.json` 的 `monitor` 段新增 `screen_width: 0.5`；
`screen_aspect` 语义改为：`<=0` 自动跟随 feed 分辨率（默认），`>0` 才强制指定。

**验证（实测，非目视）**：`_diag_feeds()` 升级为三项硬指标，4 路全 OK、运行期零 error/warning：
```
[diag] 4 路：uv=(0,0)..(1,1) OK | aspect feed=1.3333 == mesh=1.3333 OK | 内容重心≈(0.50,0.49) OK
[aim]  Port(-45,0,0) / Stbd(45,0,0) / Dorsal(0,30,0) / Ventral(0,-30,0) → 各自朝 60m 标记
[markers] 距离=60.0m（JSON 驱动）；把 marker_distance 改 100 → 标记与相机联动，重心仍 (0.499,0.496)
```

## 新增可复用探针脚本（`scripts/tests/`）
- `uv_probe.gd`：headless dump 任意 Mesh 的顶点/UV/法线（按面分组统计 UV 区间）——查「贴图只显示一角 / 重复 / 错位」的第一手段。
- `cam_probe.gd`：按 pos/target/up 算 Transform3D 并打印成 `.tscn` 可粘贴格式，让编辑器保存的相机位姿 == 运行时 `look_at` 结果。

## 收尾：数值外置
1. **4 路 feed 相机位姿外置**：删掉脚本里的 `FEED_CAM` 常量，改由 `presentation.json` 的 `monitor.feed_cams` 驱动（`feed`/`marker`/`axis`/`standoff`/`up`）。**看向点 = 标记的实际世界坐标**，所以改 `marker_distance` 时相机自动跟随。
   - 兜底：`standoff` 缺省 → 标记距离 × 0.75（仍然不 hardcode 坐标）；`up` 与 axis 共线 → 自动换正交轴；解析结果缓存在 `_feed_cam_cache`。
   - **顺序陷阱**：必须「先摆标记、再解析配置」，否则 standoff 兜底按摆放前的旧距离算（dorsal 曾错算成 33.75 而非 45）。
2. `screen_depth: 0.02` 删除（QuadMesh 无厚度，语义已死，全局零引用）。
