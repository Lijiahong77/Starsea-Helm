### 评估结论（详见 D:\GameProject\doc\EVALUATION.md）

1. 主炮改为「点击目标 → 自动转向射击」，把操作收敛到"看屏幕"单一通道（同时利好 VR 迁移）。

4. 单局目标 8–12 分钟（约 10–15 波）。
5. MVP 验证指标：3 分钟复玩意愿 / 首次死亡可归因性 / **朋友是否真的在用监控屏**（验证微创新是否成立）。

### 用户澄清的 4 点（全部采纳）

### 本轮新增设计（我方贡献，已写入文档）
- **DEC-003 前扇区无副炮**：三扇区各 120°，主炮守前（可转向）、副炮 L/R 固定守左右，**前扇区没有副炮** → 主炮一走前方裸奔。这让「主炮守哪」成为核心决策。（若前扇区也有副炮，主炮移动就失去意义。）
- **DEC-006 弱点机制**：监控标记弱点 → 主炮打弱点（2.5–4x）→ 副炮打不到。把监控与主炮串成一条动词链，同时是反挂机核心手段。
- **DEC-004 能源移出战斗**：改为改装阶段的能源预算约束（模块有能源成本，总预算缓慢提升）。
- **DEC-008 反挂机条款**（本轮新发现的风险，与首轮相反）：副炮全自动 + 主炮不需一直操作 + 监控只看一眼 + 能源移出 = **玩家可能变成观众**。护栏：副炮合计 DPS 仅够清前 3–4 波、弱点必须手动打、主炮离开前扇区裸奔、转向延迟 1.5–3s。判据：不操作能撑到第 8 波 = 失败。目标状态「手指是闲的，脑子是满的」。

### 新增决策（DEC-024 ~ 028）
- **DEC-024** 渲染器 Forward+；确立**「战场是 3D 的，界面是 2D 的」**边界。
  砍 TAA 用 MSAA —— 监控屏文字清晰是信息生命线。
- **DEC-025** 单位尺度 1 unit = 1 m，**由三个约束反推**（不是拍脑袋）：
  ① 人的尺度真实 → 舰桥 6.0×5.0×3.0 m，眼高 1.60
  ② **舷窗视野角 = 2·atan(舷窗宽/2/站位距离)**，宽 4.4 + 距 1.7 → 105°（落在 DEC-007 的 100–120°）
  ③ 威胁窗口 ≥ 8s（反应 2s + 转向 3.5s + 余量）→ `(190−50)/速度`：小型 8.2s / 中型 12.7s / 重甲 17.5s
  ④ 进场可见度 ≥ 15px@720p → 小型 18.6 / 中型 43 / 重甲 62
  飞船 64×22×16 m。
- **DEC-026** **舰桥只有艏部一面舷窗** —— 这是 DEC-007 信息不对称的**物理保证**。
  四面都有玻璃 = 玩家转头直接看后面 = 监控当场失去意义 = 微创新崩塌。**白盒第一天就要做对。**
- **DEC-027** 监控屏三档方案（A 全实时 / B 按需 / C 纯 2D 雷达）。
  ⭐ **核心认知：监控的本质是信息，不是画面** → 方案 C 零渲染成本且完全承载玩法 → 性能有逃生舱。
  Prototype 用 C，MVP 再上 A/B。
  配套：六扇区总览屏放**正前下方控制台**（下倾 25–35°），玩家平视舷窗时用余光读 —— 这是「监控只需简单看一看」的物理实现，放侧墙会逼玩家反复转头、低 APM 设计立刻崩。
- **DEC-028** 跳过纯白盒，直接用 CC0 素材（Kenney / Quaternius / Poly Haven）。替换顺序：舱室 → 控制台 → 敌人 → 炮塔 → VFX。

### 本轮最有价值的三个洞察（下次开工前必读）
1. **舷窗视野角是几何量不是配置项**。想调「监控有多必要」，调 `viewport_width` / `console_distance`，不要调什么「视野角度」参数。
2. **弹丸有飞行时间 → 所有自动火力必须做线性提前量预测**（主炮指派后自动射击 + 4 门副炮）。1 秒内敌人移动 1–3 个身位，不预测永远打不中。写共享 `LeadPrediction` 工具函数。
3. **监控性能有逃生舱**：最坏退回纯 2D 雷达，玩法零损失。Prototype 不要卡在 SubViewport 上。
